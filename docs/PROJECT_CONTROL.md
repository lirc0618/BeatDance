# 对拍：项目总控手册

版本：v2.0  
用途：唯一决策依据，防止项目重新滑回“整舞 AI 教练”。

## 0. 北极星

**Feed 暂停 → 表达卡点 → 上传模仿 → 定位一个差异 → 搜索三种拆法 → 二练验证。**

魔法时刻：系统停在关键帧，说清“你不是整段不会，而是右臂早了半拍”，并立刻给出三条对这个动作和卡点下药的内容。

## 1. 五条不变原则

1. 分析对象必须是 3–8 秒片段，不是整支舞。
2. 每次只指出一个当前最关键的卡点。
3. 诊断后必须进入内容搜索，不能停在分析报告。
4. 搜索结果必须至少有两种不同视角或拆法。
5. 没有二次验证，就不算解决问题。

## 2. 防跑偏红线

出现以下任一需求，默认拒绝：

- 加整舞总分、排名或专业评价；
- 加视频云盘、课程表、练舞天数统计；
- 先做任意动作，再补稳定性；
- 把三个搜索结果退化为同一个教程链接；
- 用长篇 AI 文本替代可视化和内容召回；
- 为“看起来像 AI”而把 VLM 放进精确计算主链。

## 3. P0 范围

- 3 个 Feed 参考片段；
- 4 种用户关注意图；
- 3 类卡点诊断；
- 每个动作至少 5 条内容标签；
- Top-3 多样化检索；
- 二练验证；
- 微信小程序 + H5 + FastAPI + Docker + Skill。

## 4. 变更闸门

新增功能需同时满足：

- 强化五项评分中的至少一项；
- 不削弱 Feed 触发和状态搜索叙事；
- 预计不超过 2 人时；
- 有明确验收标准和回滚方案；
- 一项进入，一项退出。

## 5. 阶段闸门

- G0：差异化定位冻结；
- G1：3 个参考片段和标签库就绪；
- G2：真人卡点诊断稳定；
- G3：Top-3 检索和二练跑通；
- G4：微信 / H5 / 公网部署稳定；
- G5：90 秒 Demo 与竞品问答通过；
- G6：冻结交付。

当前阶段：**G1 → G2 真人标定。**

## 6. 止损规则

- 两轮标定准确率仍 < 60%：收缩为 1 个动作、2 类卡点；
- P95 > 30 秒：降 FPS / 分辨率，豆包退出同步主链；
- 搜索结果同质：强制按 `view_type` 去重；
- 微信真机阻断：H5 升为主入口；
- 现场上传不稳：固定样例为主演示，真人上传为加演。

## 7. 4 人责任

- A 产品 / 设计：Feed 触发、交互、Demo、竞品答辩；
- B 前端：微信小程序、H5、结果搜索卡、二练；
- C 视觉算法：MediaPipe、归一化、镜像、关键帧；
- D 后端 / 检索：FastAPI、DTW、标签检索、豆包、部署与测试。

## 8. 每次站会只回答五个问题

1. 当前是否仍然是 Feed 片段问题？
2. 今天哪个真人卡点被稳定识别？
3. 诊断能否召回三种不同拆法？
4. 二练能否验证改善？
5. 有什么功能正在把产品拉回整舞教练？
